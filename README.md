# netdoctor

Windows 网络环境诊断器。一次性看清那些**配错了很难自己发现**的设置：系统代理是不是还开着、虚拟网卡的 MTU 是不是被写成了 9000、有没有残留的安全软件驱动和进程。

```text
netdoctor 1.0.0 · Windows 网络环境诊断
──────────────────────────────────────────────────────────────
[✗] 系统代理          已开启 → 127.0.0.1:10808
[·] TUN 网卡 MTU      没发现虚拟网卡（可能用的是系统代理模式，或代理没开）
[✓] 残留驱动 / 服务   没发现 360 系残留
[✓] 残留进程          没有安全软件在后台运行
[✓] hosts 文件        2 条有效记录
──────────────────────────────────────────────────────────────
发现 1 项需要关注，其中 1 项会直接影响联网。
可自动修复：系统代理
运行 python netdoctor.py --fix 处理（改 MTU 需要管理员权限）。
```

## 定位

这是一个**网络与系统配置的检查工具**。它只读取公开的系统设置（注册表里的代理项、网卡参数、服务列表、hosts 文件），不读取、不注入、不修改任何第三方程序的内存或进程，也**不针对任何特定游戏**，不含任何规避检测的功能。

做它的原因很具体：同一台机器上，代理软件和游戏客户端经常因为这三件事互相打架——系统代理没关、虚拟网卡 MTU 被设成 9000、安全软件卸载后驱动还留在系统里。这些状态在图形界面里都藏得很深，出问题时又不报错，只能靠一个个翻。

## 检测什么

| 项 | 怎么判断 | 为什么重要 |
|---|---|---|
| 系统代理 | 读 `HKCU\...\Internet Settings` 的 `ProxyEnable` / `ProxyServer` | 代理开着时，很多客户端会走错出口，表现为「连不上」但没有任何提示 |
| TUN 网卡 MTU | 列出 IPv4 接口，按名字匹配 `tun` / `wintun` / `wireguard` / `xray` / `clash` 等 | 被写成 9000（巨帧）时流量要反复分片，网络会明显变慢 |
| 残留驱动 / 服务 | 查 `System32\drivers` 下已知文件 + 扫注册表服务名 | 安全软件卸载后驱动常留着，与某些反作弊组件冲突，表现为莫名掉线 |
| 残留进程 | 按进程名匹配已知安全软件 | 后台还在跑的话，关掉再试往往就好了 |
| hosts 文件 | 统计有效记录数 | 用过加速器或「防自动更新」工具后，条目容易堆积且忘记还原 |

MTU 这一项只对**虚拟网卡**报警。物理网卡的 9000 可能是正常的万兆设置，WireGuard 默认的 1420 也低于 1500，这两种都不该算问题。

## 用法

只需要 Python 3.8+，**没有任何第三方依赖**。

```bash
# 看报告
python netdoctor.py

# 机器可读
python netdoctor.py --json

# 修复能自动处理的问题
python netdoctor.py --fix

# 只关代理 / 只改 MTU
python netdoctor.py --fix proxy
python netdoctor.py --fix mtu
```

`--fix` 会做两件事：

- **关系统代理**：改 `ProxyEnable = 0`，并调用 `InternetSetOption` 让系统立即生效，不用重启
- **把虚拟网卡 MTU 改回 1500**：`netsh interface ipv4 set subinterface ... mtu=1500`，**需要管理员权限**

残留驱动和进程**不会自动处理**。删驱动风险太高（删错可能开不了机），工具只告诉你文件名和服务名，让你自己去「服务」里禁用。这是刻意的取舍。

## 退出码

方便塞进脚本或定时任务：

| 退出码 | 含义 |
|---|---|
| 0 | 全部正常 |
| 1 | 有需要关注的项（`warn` 或 `bad`） |

想每天早上自动检查一次：

```powershell
# 任务计划程序里加一条，登录时运行
python C:\path\to\netdoctor.py --json > C:\path\to\netdoctor-$(Get-Date -Format yyyyMMdd).json
```

## 测试

```bash
python -m unittest discover -s tests -v
```

21 项，覆盖 MTU 判定的各种网卡命名、hosts 的边界情况、报告对齐等。测试只碰纯逻辑和临时文件，不会改你机器上的任何设置。

## 已知边界

- 只支持 Windows。Linux / macOS 的接口查询方式完全不同，没有做兼容
- hosts 只统计不改写——自动改 hosts 太容易出事
- 不检查 DNS、路由表、Winsock LSP。这些需要的信息更多，误报率也更高
- `--fix mtu` 改的是当前网卡的持久化设置。如果你的代理软件每次启动都会重写 MTU，那得在它的配置里改，工具管不了
